# 09: 完成端到端验收与新旧入口迁移

**What to build:** 对完整计划执行流程完成跨功能验收，发布可使用的 herdr-plan-manager 入口及迁移说明，在新实现验证通过后移除被替代的旧实现，让用户能够从完整工单集运行到目标收口。

**Blocked by:** 08 — 跑通新 worker 修复冲突与整体目标收口。

**Status:** ready-for-agent

> 迁移基准（工单 05 已集成：`0ee66d7`）：新入口的 CLI 与存储布局以工单 05 落地的 `init-run`／`start --run`／`status --run`／`wait`／`ack` 及 `runs/`、`workers/<id>/ack.json` 为准；最终验收报告需覆盖这些入口与 README E07。

> 迁移基准（工单 06 已集成：`3a60d48`）：端到端验收需覆盖 `stop` → `cleanup` 流程与清理决定语义（未提交内容的归档／丢弃、默认保留分支、只关闭登记 tab、结果与交接证据保留）；入口与存储以 README E08 为准。

## 依据与边界

依据：[项目重建方案](../项目重建方案.md)第 11、12、13 节。

本工单补充必要的跨功能验证，复用已经充分的工单证据，不把前序验收全部机械重跑。发现具体缺口时记录并推动修复，不能靠放宽完成条件通过最终验收。

## 验收条件

- [ ] 为方案的 12 个验收场景建立证据对应关系，明确哪些来自前序工单、哪些是最终组合验证；真实双运行时冒烟与确定性故障模拟各自标明，不把 mock 结果冒充运行时实测。
- [ ] 实际验证从确认完整输入与显式配置，到多 worker 动态推进、交接、交付、集成、必要修复及整体收口的完整路径。
- [ ] 重点补验双运行时自动交接与并发额度、wait／ack、停止和清理的交互，保证会话替换不重复领槽、不漏报异常、不产生并行写入。
- [ ] 新 skill 名称、说明、调用入口和内部引用统一为 herdr-plan-manager；目录迁移遵循实际安装关系，验证调用者能够找到新入口和引用材料。
- [ ] 使用与迁移说明包含输入、配置、动态执行方法、工具操作、结果／资源位置及明确的首版边界。
- [ ] 新实现验证通过后移除旧固定批次入口、Codex 适配、严格工单解析及被替代的 schema／测试，复用能力仍有针对性验证。
- [ ] 不建设复杂旧批次接口转换层，不自动把旧状态解释为新状态，不自动接管或清理旧 worker、分支或 worktree。
- [ ] 最终执行不依赖固定四轮问答、批次屏障、任务时间／费用预算、主脑亲自修复或主脑恢复系统。
- [ ] 交付最终验收报告、可重复的必要操作步骤及任何尚未解决事项；有阻塞目标的缺口时明确报告未完成。

## 验证重点

汇总并核验场景 1—12。通过主脑实际使用新入口验收，不只检查文档改名或测试数量。
