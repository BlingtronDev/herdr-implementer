# 08: 跑通新 worker 修复冲突与整体目标收口

**What to build:** 主脑在集成发现冲突或组合行为问题后，创建并派发新工单，由新 worker 在隔离工作目录修复和验证，再由主脑组织集成。主脑最终依据 spec／计划目标和证据判断整体完成。

**Blocked by:** 07 — 交付主脑动态管理计划的 skill。

**Status:** ready-for-agent

## 依据与边界

依据：[项目重建方案](../项目重建方案.md)第 3、4.3、9 节。

本工单补齐并验证主脑方法与必要的工单材料支持，不创建自动合并服务，也不让主脑成为冲突修复 worker。新增修复、调查和验证工作仍使用普通单工单执行接口。

## 验收条件

- [ ] 文本合并冲突发生时，主脑记录目标基线、incoming 成果、冲突摘要及相关要求，不修改冲突文件解决问题。
- [ ] 对自己发起的合并使用可控中止流程恢复目标；无法确认前置条件、中止失败或涉及无法区分的用户工作时保留现场并报告，不强行 reset。
- [ ] 新修复 worker 从明确基线建立隔离集成分支，获得双方成果和相关工单要求，复现冲突、修复并验证兼容意图；主脑随后检查交付并组织集成。
- [ ] 修复期间目标发生变化时，主脑重新判断兼容性，必要时派新修复工单；已知问题解决前不解锁相关依赖，可继续安排无关工作。
- [ ] 无文本冲突但组合行为错误时，主脑同样新增修复或验证工单，由新 worker 实施，不亲自修代码。
- [ ] 最终收口对照 spec／计划目标、集成结果与遗留问题；必要整体验证由 worker 执行，已有充分证据可复用，不强制固定最终验收角色。
- [ ] 初始工单均交付但组合验证失败时，主脑继续派工而不报告整体成功；最终报告列明验证依据、未解决事项和保留资源。
- [ ] 提供文本冲突及行为冲突两种可重复场景的证据，能够确认实际修复由新 worker 完成，整体判断由主脑承担。

## 验证重点

覆盖验收场景 7、8，并检查场景 6 的交付／集成语义在修复工作中仍成立。
