# 08: 跑通新 worker 修复冲突与整体目标收口

**What to build:** 主脑在集成发现冲突或组合行为问题后，创建并派发新工单，由新 worker 在隔离工作目录修复和验证，再由主脑组织集成。主脑最终依据 spec／计划目标和证据判断整体完成。

**Blocked by:** 07 — 交付主脑动态管理计划的 skill；08-R1、08-R2 — 本轮补充测试修复与成功终端释放（均已交付并纳入当前工作区）。

**Status:** integrated（2026-09-13 核实：含 08-R1、08-R2 的成果已进入 main，提交 `759d721`；09 前置满足。下方未提交描述保留当时交付事实。）

## 依据与边界

依据：[项目重建方案](../项目重建方案.md)第 3、4.3、9 节。

本工单补齐并验证主脑方法与必要的工单材料支持，不创建自动合并服务，也不让主脑成为冲突修复 worker。新增修复、调查和验证工作仍使用普通单工单执行接口。

## 验收条件

- [x] 文本合并冲突发生时，主脑记录目标基线、incoming 成果、冲突摘要及相关要求，不修改冲突文件解决问题。证据：Pi `before-B`、`conflict-*`、R 合同。
- [x] 对自己发起的合并使用可控中止流程恢复目标；无法确认前置条件、中止失败或涉及无法区分的用户工作时保留现场并报告，不强行 reset。证据：Pi `abort`／`after-abort`，真实 Git 故障注入 `abort-boundaries.json`。
- [x] 新修复 worker 从明确基线建立隔离集成分支，获得双方成果和相关工单要求，复现冲突、修复并验证兼容意图；主脑随后检查交付并组织集成。证据：Pi `w08-pi-r` 原生工具调用／输出、`integration.json`。
- [x] 修复期间目标发生变化时，主脑重新判断兼容性，必要时派新修复工单；已知问题解决前不解锁相关依赖，可继续安排无关工作。证据：R 活跃时合并无关文档，`target-delta` 与兼容性决定；行为相关目标移动的再派工分支为文档流程审查，非真实第三场景。
- [x] 无文本冲突但组合行为错误时，主脑同样新增修复或验证工单，由新 worker 实施，不亲自修代码。证据：OpenCode `combined-failure`、`w08-opencode-r` 源码编辑／提交及回归输出。
- [x] 最终收口对照 spec／计划目标、集成结果与遗留问题；必要整体验证由 worker 执行，已有充分证据可复用，不强制固定最终验收角色。证据：两组 R 组合验证及主脑集成映射；新增 goal coverage 模板。
- [x] 初始工单均交付但组合验证失败时，主脑继续派工而不报告整体成功；最终报告列明验证依据、未解决事项和保留资源。证据：OpenCode `repair-inputs` 从 executing 转至集成后的 complete；证据索引列明保留现场。
- [x] 提供文本冲突及行为冲突两种可重复场景的证据，能够确认实际修复由新 worker 完成，整体判断由主脑承担。证据：`smoke.py` 逐项操作、合同／结果／运行时工具调用及输出。
