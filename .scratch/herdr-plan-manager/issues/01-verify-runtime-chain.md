# 01: 验证 Herdr 与双运行时的最小执行链路

**What to build:** 在一次性仓库中验证 Pi 和 OpenCode worker 从显式配置、Herdr 启动、任务投递到暂停及文档交接的最小链路。交付可重复的冒烟步骤和实际生效证据，为新工具选择有依据的适配方式。

**Blocked by:** None (can start immediately).

**Status:** delivered（验证记录与证据：[../evidence/01-verify-runtime-chain/README.md](../evidence/01-verify-runtime-chain/README.md)；待主脑确认集成）

## 依据与边界

依据：[项目重建方案](../项目重建方案.md)第 2、5、8 节及实施阶段一；使用项目领域词汇表中的主脑、worker 和 worker 交接定义。

本工单是有限的集成验证，不建设完整生命周期工具。只使用明确属于本次实验的资源。运行模型实验前须取得明确的运行配置与并发授权，不能凭安装情况选择默认模型。

## 验收条件

- [x] 记录实际 Herdr、Pi、OpenCode 及官方集成版本；区分只读发现、实际实验结果和未验证假设。
- [x] 两种运行时分别使用显式 provider、model、thinking 启动，并提供可核对的实际生效证据；不支持的组合明确报告，无静默降级或默认模型回退。
- [x] 验证 OpenCode 可用的推理配置注入方式，既不改写业务仓库配置，也不为设置模型覆盖整个权限配置。
- [x] 验证 Herdr 启动就绪、prompt 接受、working、idle/done、blocked 和等待超时的实际语义，明确哪些信号不能证明工单完成。
- [x] 验证 Pi、OpenCode 对应的暂停方式、handoff skill 调用方式，以及新会话读取交接文档后继续同一工作目录的最小实例；不假定两者都支持字面 `/handoff`。
- [x] 验证主脑工具调用返回后监督逻辑仍可运行，后续调用可读取状态与结果；说明适用的后台进程启动方式。
- [x] 交付可重复的冒烟步骤、资源与结果定位方式、推荐适配策略及已知限制；历史兼容补丁仅在复现或存在明确版本依据时建议保留。
- [x] 实验结束后按明确决定清理本次资源，保留验证证据；不操作其他会话或工作目录。认证等外部条件阻塞实验时明确报告，不能把未执行项目标为通过。

## 验证重点

覆盖重建方案验收场景 1 的实际配置依据，并为场景 3、4 提供真实运行时操作依据。本工单结束不代表自动交接工具已经实现。
