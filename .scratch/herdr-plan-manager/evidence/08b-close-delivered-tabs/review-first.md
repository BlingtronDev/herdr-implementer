# 08-R2 首轮审查：交付前处理

此为同一工单的验收复核，不扩展目标。审查时实现尚未提交。

## 必须修正并验证

1. `live_session_facts` 把 agent get 的任何非零返回都当作不存在。释放路径不能将瞬态查询错误当作已退出：只有明确 agent_not_found 可作为不存在证据；错误应保留并记录原因，列表里的登记 agent 若仍 working 也必须阻止关闭。
2. 退出前采集的占用／Git 状态在退出等待后已过期。每次关闭 tab 前重新核验当前占用和工作区，确保退出期间新增未登记 pane／外来 agent／未提交内容会阻止关闭。遵循可用 API 能力，不引入全局服务。
3. supervisor 先写 delivered 再花时间退出关闭，stop 等待到期后不能因生命周期已终态就接管。只要监督 PID 仍存活，stop 不得同时写入或释放；无 supervisor 的并发 stop 也应按 worker 互斥，避免重复退出／覆盖释放记录。
4. pane_list／agent_list 响应必须校验形状与判定所有权所需字段。不能静默过滤坏元素、跳过缺少必要身份的对象后宣称 confirmed。非法非对象 result 也需转换为 ManagerError，让释放流程记录不可确认而保留。

为以上行为增加确定性的故障／竞态覆盖，已有测试仍应通过。完成后按需跑受影响测试及最终全量，交付结果逐项回应。

## 定向复查

未知 agent 查询及 supervisor/stop 并发归属问题已解决。退出后整体复查仍有一个多 tab 反例：交接留下 A、B，复查通过后关闭 A 的命令耗时，期间 B 出现新 pane/agent，随后循环直接关闭 B。请在**每个 tab 关闭前**重新核验相关占用／条件，而不是仅在整个 tab 集合关闭前复查一次，并覆盖该注入时序。Herdr 若无条件式关闭 API，不要求扩展服务端实现绝对原子保证；明确当前能力边界即可。

## 可选简化

退出按键/等待与 `end_session` 存在重复。可优先复用带可选 timeout 的底层退出操作，保持释放前置条件独立；不为消除几行重复而扩大设计。
